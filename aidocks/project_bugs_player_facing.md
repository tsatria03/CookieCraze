# Player-facing bugs (audit of 6.8, 2026-09-30)

A full-game review (five parallel reviewers, the worst re-verified by hand) produced this list. Nothing was fixed at audit time. **Line numbers are from 6.8 — re-locate by symbol before fixing** ([[feedback_verify_code_while_fixing]]). Exploits and balance live in [[project_bugs_exploits_balance]]; internal code defects in [[project_bugs_code]]; build/docs in [[project_bugs_build_docs]]. Mark an entry **FIXED (version)** when it ships rather than deleting it.

**Mirrored in `cycrz/docks/todo_list.txt` (2026-09-30):** every open High and Medium item here (#1–#4, #6–#11, #14–#19; not #13's code mismatch, not the Low convention items #20–#31) has a `****Unfinished.` line there, and the fixed ones (#0, #5, the slots bet timing, #12/#13 readme) have `**Finished.` lines ([[feedback_todo_list_format]]). **When you fix one of these, also move its todo line to the finished section.**

## Fixed since the audit

0. **FIXED (6.9)** — **Store crash "Index out of bounds" in `bundlecategorymenu`** (dev-reported 2026-09-30, not caught by the audit). The gained-items sentence was joined with `if 1 / else if 2 / else loop to length()-1`; with an EMPTY list `length()-1` wraps (uint) to 4294967295 and indexes `[0]`. The list is empty when a purchase gains only speed while `cookiespeed` is at the 950 cap ([[project_cookiespeed_cap_plan]] — `gain_cookiespeed` returns 0 applied), e.g. the speed-only Speed Demon Bundle. Three sites in `menu.nvgt` (single bundle buy, buy-one-of-every-bundle, singles buy-all). Fixed with `join_spoken_list(string[]@)` in `extrafuncts.nvgt` (handles 0/1/2/n) used at all four joins; empty gain now says "nothing new because your baking speed is already at its maximum". **Still open (design):** the store still *charges* for speed you can't use at the cap — block speed-only purchases or skip the speed portion of a bundle's cost. Rule for new code: use `join_spoken_list`, never index `length() - 1` without checking for empty.

## High — lost, leaked or duplicated progress

1. **FIXED (6.9)** — `resetgame()` full-reset branch now zeroes `prestige_points`, `prestigePurchased`, `prestigeEndlessCounts` and the three combo stats, then runs `apply_all_prestige_store_upgrades()` before `reset_game_state()`. Dev-tested. Original: **New game / start over keeps the previous slot's prestige progress.** `resetgame(false)` (`src/cycrz.nvgt`, else-branch ~221-244) zeroes `prestigeLevel` but never clears `prestige_points`, `prestigePurchased`, `prestigeEndlessCounts`, `stat_highest_combo_reached`, `stat_combos_started`, `stat_combos_broken`. `reset_game_state()` then re-adds `prestige_starting_*` bonuses and `prestige_rank_discount` computed from the leftover purchases. Repro: prestige 10 on slot 1, new game on slot 2 → slot 2 starts with slot 1's points, store upgrades and head start. Fix: clear those six in the full-reset branch, then `apply_all_prestige_store_upgrades()` before `reset_game_state()`. (Verified.)
2. **FIXED (6.9)** — unlocked ids saved as `achievementCount` + `achievement_<i>`; `readdata` restores them then runs `init_achievements`; `reload_config` no longer wipes them; menu count only counts ids still in the table. Dev-tested. Original: **Achievements are not saved — reloading after a prestige re-locks them and re-pays their rewards.** `writedata`/`readdata` never persist `achievementsUnlocked`; every load rebuilds it from current stats via `init_achievements` (`achievements_table.nvgt` ~152; callers `cycrz.nvgt` ~68, `menu.nvgt` ~156, `extrafuncts.nvgt` ~481 Ctrl+L). Prestige zeroes per-run stats (`stat_cookies_baked`, `stat_baker_events_fired`, `stat_flipper_flips`…). Repro: prestige, save, reload → Baking/Economy achievements locked; re-crossing pays e.g. `event_force` (10000*rank cookies) again; 41 achievements carry rewards. Contradicts the prestige prompt ("achievements are kept", `menu.nvgt` ~2378). Fix: save count + ids; only rebuild from stats when the key is absent (old saves). (Verified.)
3. **Saving settings from the main menu overwrites the last slot with discarded progress.** The Save button in game settings runs `writepreffs(); writedata(); readdata();` unconditionally (`settings_menu.nvgt` ~117-120); `sd` still points at the last slot. Repro: load slot 1, play, "quit without saving", open settings, Save → the unsaved run is written to slot 1. Fix: guard with `if (ingame)` — settings only need `writepreffs()`. (Verified.)
4. **An interrupted save can silently wipe a slot.** `savedata::save()` (`deps/savedata.nvgt` ~40-50) opens the real file with `"wb"` (truncates immediately), no temp file/rename, no backup, no open check, no close. A truncated file fails AES decrypt → `deserialize` returns an empty dictionary with no error → `readdata` changes nothing (only assigns keys that exist) → player keeps whatever was in memory (defaults or another slot) and the next save makes it permanent. The load menu still lists the slot (only checks `file_exists`). Fix: write `fn+".tmp"`, close, rotate old to `.bak`, rename; on load, if empty/no `rank`, try `.bak` and say so. (Verified.)
5. **FIXED (post-6.9, 2026-09-30)** — `minigame_input` now reads the status letters (C/A/S/M/O) only while Control is up, and Ctrl+S **saves in place** (no `form.reset()` / minigame restart), so a mid-round save never abandons a round whose bet was already taken. Prerequisite done in the same change: **slots now takes the bet up front** at spin (like blackjack/dice/highlow/roulette), a win returns bet + winnings (net payout unchanged), and a spin with no matching payout row refunds the bet. Readme "In minigames." block now lists Control S. Main-game Ctrl+S still restarts `clickergame()` (harmless there, part of code bug #13 recursion). Original report: **Ctrl+S never saves inside any minigame.** `extrafuncts.nvgt` minigame key handler reads plain `key_pressed(KEY_S)` (~907, announces auto cookie speeds) before the Ctrl branch reads it again (~917) — the first read consumes the press ([[project_nvgt_key_pressed_oneshot]]; confirmed in legacy `input.cpp`). **Fix ordering hazard:** once Ctrl+S works, saving during the slots payout wait restarts `slotsgame()` and skips the loss — make slots deduct the bet up front first (see [[project_bugs_exploits_balance]]). Fix: `bool s = key_pressed(KEY_S);` then branch on `control_is_down()`, or guard ~907 with `!control_is_down()` like `game.nvgt` L. (Verified by three reviewers.)
6. **Menu search (F3) rejects all letters after any purchase prompt.** `vd` is a single global (`dec.nvgt` ~240); store quantity prompts call `vd.set_disallowed_chars(<all letters>)` (`menu.nvgt` ~507, 697, 1180, 1288, 1639) and never clear it; `input_box` always applies it (`virtual_dialogs.nvgt` ~142-145); the menu search (`custom_menu.nvgt` ~218) reuses `vd`. Fix: `vd.set_disallowed_chars("")` before the search box (or reset at the end of `input_box`).
7. **Game settings Cancel/Escape doesn't undo.** Sliders/checkboxes write straight into live globals every loop (`settings_menu.nvgt` ~75-93); Cancel/Escape (~123-130) just returns. Repro: raise sell price to 100 cents, Cancel → cookies sell for $1.00 until reload. Same for gender in user settings (~275) and volume sliders in audio settings (~170-173; live preview is fine, but Cancel should restore). Fix: snapshot on entry, restore on Cancel/Escape.
8. **Leaving blackjack or higher-or-lower mid-round silently forfeits the bet** (and the unbanked higher-or-lower pot). Escape calls `mingamsmenu()` while `in_round` after the bet was deducted (`minigames.nvgt` ~459-463 blackjack, ~1036-1040 highlow); no loss stat recorded. Fix: refuse to exit mid-round, or settle it (count the loss / bank the pot).
9. **Ctrl+L re-rolls active quests for free.** `readdata()` restores the saved quests, then `reload_config(true)` calls `assign_quests()` (`extrafuncts.nvgt` ~486), discarding them and picking a new random set — no reroll cost, no `questRerollCount`. Also via minigame Ctrl+L (~936-939). Fix: don't re-assign in `reload_config` when a save was just loaded (or only when `activeQuests` is empty).

## Medium

10. **Dice results are silent** — `minigames/dice_roller/win.ogg` and `lose.ogg` are referenced by `dice.table` result rows but don't exist in `cycrz/sounds/`.
11. **Announcements always cut off current speech.** `buffer.nvgt` ~76 speaks every item with `speak(itemname, true)`, and `speak_buffer` defaults to interrupt (`speech.nvgt` ~18,35); the buffer class's own `interrupt` field (~13) is never used. An achievement/combo/event message cuts off a menu item or the R readout. Fix: honour `buffers[b].interrupt` (default false for achievements/combos/events).
12. **README FIXED (2026-09-30, post-6.9 commit)** — readme now documents the real behavior (exports focused buffer, appends to `logs/<name>.log` under a date, clears on success, empty buffer says nothing to export). Code unchanged and **correct as is**: per-buffer export is intentional and there is deliberately no "export all" key (dev-confirmed; see [[project_message_buffers]]). Fully closed — the only bug was the readme. Original: **Shift+Backslash exports only the focused buffer and then clears it**; readme (~500, ~534) said it exports all. `game.nvgt` ~349-354, `buffer.nvgt` ~298. Fix: `export_all_buffers()` without clearing, or document and announce the clear.
13. **README FIXED (2026-09-30, post-6.9 commit)** — added an "In minigames." key block to the readme (C, A, S, M, O, Control L) with a note that M is manual cookies and O is money there. Control S added to that block once #5 was fixed. The letter mismatch itself is unchanged in code. Original: **Minigame status keys disagree with the main game.** Main game M = money (`game.nvgt` ~387); in minigames M = manual cookies, O = money, plus A and S (`extrafuncts.nvgt` ~905-913). Minigame keys aren't documented anywhere. Fix: unify letters, or add a "Minigame keys" readme block.
14. **Quest reroll asks the same Yes/No twice** with warning modes 2/3/4 (`menu.nvgt` ~2285-2298 then again ~2342-2352). Warning mode 5 on a completed quest (~2277-2282) reloads the menu with no message.
15. **Store is locked with less than 1 cent, and selling lives inside the store.** `game.nvgt` ~185 blocks entry; sell is in the store (`menu.nvgt` ~457). A new player who spends the starting 10 cents can't sell cookies until a rank-up pays cash. Fix: also allow entry when cookies ≥ 1.
16. **Baking-speed events can wipe all speed at once.** `baker.event` gain `10/rank` vs loss `10*rank`; `apply_event` clamps to 0 (`baker_events.nvgt` ~71-73). From rank 95 one "decrease" event removes the full 950. Flipper has the same shape (`flipper.event` `5/rank` vs `5*rank`). (Also listed as balance.)
17. **Baker info mislabels quest mode `require_all=1`** as "reward if any quest is complete" (`extrafuncts.nvgt` ~521); mode 1 never gives a reward (`quests_table.nvgt` ~437, readme ~1623).
18. **Dice can keep the bet on a misconfigured table** — if no `-1` row exists, ~918-921 reports an error after deducting without refunding. With `max_dice_count` < 6, ~766 sets a negative list position.
19. **Hitting to exactly 21 in blackjack wins instantly** (`minigames.nvgt` ~594-610) — the dealer never plays, so a hand the dealer would push counts as a win; message is hardcoded instead of `win_message`.

## Low — UX / convention violations

20. **"canceled" is almost never spoken** ([[feedback_menus_say_canceled]]): only 3 of ~40 `m.run()` sites. Examples: docs/game/load/new-game menus (`menu.nvgt` ~56, 98, 135, 190), new-game overwrite No/Escape (~207, 225), reroll No (~2293, 2347), prestige No (~2386 — also dumps you in the main game screen instead of the quests menu), minigames Escape (~261), preferences Escape (`settings_menu.nvgt` ~25), minigame confirm prompts (`minigames.nvgt` ~318, 522, 889, 1108, 1436). Search box says "Cancelled." (different spelling, `custom_menu.nvgt` ~221).
21. **Cancelling a quantity or name box reports an error** instead of "canceled": `vd.input_box` returns "" → parsed as 0 → "Error! Please enter a valid number…". Sell (`menu.nvgt` ~509-515), tickets (~698-703), bulk buy (~1181-1187), singles (~1297-1303), bundles (~1641-1647), first/last name (`settings_menu.nvgt` ~279-283, 299-303). ~947 and ~1572 return silently instead.
22. **Yes/No label violations** ([[feedback_yes_no_menu_labels]]): lowercase "yes"/"no" with position-based checks at `menu.nvgt` ~203-204 and `cycrz.nvgt` ~105-106; profile-setup Escape on the Yes/No exits the whole game (`cycrz.nvgt` ~109-112). `game.nvgt` ~490-493 uses four long options (a four-way choice — possibly a legitimate exception).
23. **One-sentence rule violated 60+ times** ([[feedback_one_sentence_game_messages]]): `dlgmessage_return` always appends " Press enter or space to continue."; ~51 messages lead with "Error!", "Success!", "Purchase successful!", "Sorry…" as a separate sentence. Minigame lock message is three sentences, copied 7× (`menu.nvgt` ~271-361). `menu.nvgt` ~1574 includes "Press enter or space to continue." itself → spoken twice.
24. **Raw unformatted numbers still spoken**: prestige store intro `string(prestige_points)` (`menu.nvgt` ~835; also typo "brows" → "browse"), ~657 tickets you can buy, ~903, 984, 994, slot counts ~1785, 1813, 1857, 1878, 1995. Fix: `format_number`.
25. **Coin sound gaps** — `play_coin_sound` (`extrafuncts.nvgt` ~453-461) has ranges (491–499, 9991–9999, …) where no sound plays. Fix: use `<` bounds.
26. **Silence at buffer edges** (`buffer.nvgt` ~189-193, 209-213) — no sound or speech at the ends.
27. **Menu Home with nothing focused speaks the current item** instead of jumping to the first (`custom_menu.nvgt` ~473-479). Position announcement ("3 of 20") hard-wired off (~6), no setting.
28. **No in-game key help**; the key list exists only in the readme (starting ~line 502 of 1841).
29. **Last-name error path** (`settings_menu.nvgt` ~302-304) plays the error sound without storing its slot, then destroys whatever `alertslot` held.
30. **Slots freezes input 1–2 s** (`minigames.nvgt` ~342 plain `wait()` instead of `mini_wait_async`).
31. **Earnings-per-sell can display Inf** (`extrafuncts.nvgt` ~512: `floor(cookies)*cookieSellPrice` not `safe_cap`ped).
