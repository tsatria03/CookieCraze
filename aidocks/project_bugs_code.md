## Save / load

1. **(Backup part WON'T FIX — dev declined `.bak` files 2026-09-30.)** **Unsafe save write + silent empty load** — see [[project_bugs_player_facing]] #4 (`deps/savedata.nvgt` `save()`/`load()`). The vendored `savedata.nvgt` is also *older* than the legacy fork's: it lacks the fork's missing-file guard in `load()` and the explicit `f.close()` in `save()`. Port both.
2. **FIXED (6.9)** — **Achievements not persisted** — see [[project_bugs_player_facing]] #2.
3. **Saved quests restored before `completedQuestIds` is loaded** (`savefuncts.nvgt` `readdata`, active-quest block ~175-197 before completed block ~198-214). If fewer saved quest ids resolve than `max_active` (id renamed, `max_active` raised), the fallback `assign_quests()` runs against the *previous slot's* (or empty) completed list and may offer done tiers or skip open ones. Fix: move the `completedQuestCount` block above `activeQuestCount`.
4. **Unknown completed-quest ids are dropped and then erased** (`savefuncts.nvgt` ~207-212). If `quests.table` fails to load (unchecked, #9) or an id is renamed, the next save deletes those completions permanently, lowering the prestige-points multiplier. Fix: keep unknown ids in a side list and write them back.
5. **Lottery ticket counts written as double, read as int** (`savefuncts.nvgt` ~264 `sd.read_int`). Counts > 2³¹ load wrong/negative — reintroduces the bug that making `owned` a double fixed. The same loop never zeroes tickets absent from the save, so a newly added ticket id keeps the previous slot's count. Fix: `read_double`; zero every `owned` first.
6. **Slot isolation relies on `readdata` overwriting everything** — any key missing from a save (old save, empty dictionary from #1) keeps the previous slot's in-memory value. #1, #3, #5 and the new-game prestige leak ([[project_bugs_player_facing]] #1) are all instances. Structural fix: reset to defaults before every load. **PARTLY FIXED (by 7.0):** `readdata` now clears `prestigeEndlessCounts`, `questEndlessCounts`, `achievementsUnlocked` and `baking_slots` before loading; `prestigePurchased`, the histories and every scalar still keep the previous slot's value when their key is missing.
7. **Single-instance lock differs by build** — mutex name is `crc32(NVGT_VERSION_COMMIT_HASH + "cycrz")` (`deps/instance.nvgt` ~17), so a compiled release and a from-source run can both write the same saves at once.
8. **Save keys in public source** (`dec.nvgt` ~235-238), no integrity check. Fine for single-player; saves are trivially editable.

## Numeric

9. **FIXED (7.1), dev-tested** — `random_amount(min, max)` in `extrafuncts.nvgt` (random() when both ends fit in ±2e9, else `random_float()`), used for rank, baker event, prestige default and both lottery prize rolls; see [[project_rank_burst_plan]]. Original: **`int()` overflow in reward rolls.** `ranks_table.nvgt` ~79 and `baker_events.nvgt` ~58 use `random(int(minVal), int(maxVal))`. Default rank reward `100*rank` overflows past rank ~21.5M → `INT_MIN` → the "reward" drains money, and `convert_to_currency` returns "" for negatives (empty amount spoken). Fix: roll as double (`minVal + random_double * range`). **7.0 re-check:** the same `random(int(...), int(...))` pattern is now also in `lottery_table.nvgt` (prize rolls, three sites).
10. **`prestige_points` and `pointsEarned` are 32-bit `int`** (`prestige_table.nvgt` ~29, `cycrz.nvgt` ~183, `savefuncts.nvgt` ~129 `read_int`, `menu.nvgt` ~967). Overflows very late with endless completions × `10*rank`. Fix: make it double end to end.
11. **FIXED (7.1), dev-tested** — `check_rank()` loops every earned rank in one call, announces once per call (thinning kept, `[summary]` message in ranks.table, fallback to the highest thinned rank's default message), milestones paid in the loop and announced after; built per [[project_rank_burst_plan]]. The discussion notes below are kept as the design record. Original: **Only one rank-up per frame** — `game.nvgt` ~249 and `check_rank` use `if`, not `while`. A huge XP gain trickles out at ~200 ranks/s, each paying a reward and running `check_achievements`; the rank-thinning comment assumes several ranks can arrive at once.
   - **Fix discussed with the dev 2026-10-25 (not built; has a todo line):** use a `while` loop so every earned rank lands in one pass. Scale of the problem at default mods (leaving rank r needs 4 × r² XP): 20k XP from rank 1 → rank 71 in ~70 passes (<0.5 s); 1 billion → rank 15,812 (~1.5–3 min of climbing); 1 trillion → rank 500,001 (~42 min to over an hour). Final rank and rewards are identical either way — only the timing changes.
   - **Speech/sound must change with it:** keep the thinning rule (every rank to 9, every 10th to 90, …) but announce only the **highest thinned rank crossed in the pass**, once, with one set of sounds — otherwise a burst queues every thinned message back to back (ranks buffer no longer interrupts, player #11) and stacks the sounds. Normal play (one rank per pass) is unchanged.
   - **Milestones stay separate (dev decision):** every crossed ranks.table milestone still fires its own reward, unlock sound and message/dialog — e.g. rank 1 → 71 crosses seven unlocks (10 blackjack … 70 slots). The dev is fine with ~7 dialogs in a row because `dlg()` (`deps/dlg.nvgt`) closes on Enter/Space (`key_repeating`) or A (`key_down`, so holding A skips them all), and Escape. Don't propose combining them.
   - **Burst announcement — DECIDED (dev, 2026-10-25: "I like that idea quite a lot"):** a new optional `[summary]` section in `ranks.table`, one message line, tokens `%name%`, `%from%` (rank before), `%rank%` (rank now), `%ranks%` (ranks gained), `%amount%` (total of every default reward in the burst, formatted per the default reward's target — currency for coins). Shipped text proposed: "Wow, %name%! You climbed %ranks% ranks, from rank %from% to rank %rank%! You've earned a total of %amount% for your achievements. Great work!" Rules: used only when one pass gains MORE than one rank AND crosses at least one thinned rank (a 5,001 → 5,003 gain stays silent; a single rank-up still speaks the normal default message); one `play_rank_sound(total)` + one `rankach` sound; milestones unchanged (each fires afterwards). If `[summary]` is missing, fall back to the highest thinned rank's default message, so old/modded tables still load (parser learns one header). Needs a readme ranks.table reference update and a changelog entry when built. Example at default 100×rank cents: rank 1 → 71 totals $2,555.00. Before building, write a full plan per [[feedback_plan_features_in_memory]]. **Performance:** 500k iterations may pause briefly — build the message string only for the announced rank, and cap at ~10,000 ranks per pass if testing shows a stall. Merge the two rank-up copies (`game.nvgt` + `check_rank`, see Duplication hotspots) first so the loop is written once.
12. **Dead branch** — `game.nvgt` ~234-238 tests `autocookie<=0` inside a block that requires `autocookie>=1`.

## Control flow

13. **Recursive "loops".** `clickergame()` calls itself (`game.nvgt` ~71, 370, 384, 504, 539, 552; also from `show_baker_info`, `extrafuncts.nvgt` ~538); menus call each other (`mainmenu`→`gamemenu`→`mainmenu`, `clickergame`→`shopmenu`→`clickergame`, `prestige_store_category_menu` calls itself after each buy). Legacy engine stack is unlimited (`nvgt_angelscript.cpp` ~530-531) so it doesn't crash — it grows memory over a long session, and any path that does return falls through into the code after the call. Fix: long term, menus return results to one loop; short term, `return;` after every recursive call.
14. **`reload_config` re-parses events/slots/ranks without the startup `length()==0` checks**, and calls `assign_quests()` (see [[project_bugs_player_facing]] #9). **PARTLY FIXED (6.9):** the quest part is fixed (it restores active quests, `assign_quests` only as fallback); the missing `length()==0` checks remain, and see #29 for the tables it never reloads.

## Minigame code

15. **`stat_coins_earned` not incremented on slots wins** (~405) **or any blackjack win path** (~550, ~598, ~636); dice/highlow/roulette do. Undercounts earnings achievements/quests.
16. **Bet-flow duplication** — bet parse/×100/min/max/clamp copied 5× (`minigames.nvgt` ~260-290, 477-508, 814-845, 1063-1094, 1381-1403); confirm dialog 5×; "apply amount to chosen stat" if/else ladder ~20×; 8-line stat clamp 7×; blackjack/dice fill placeholders by hand though `highlow_fill` exists. Suggested helpers: `bet_balance(sel)`, `apply_bet_delta(sel, amt)`, `bet_item_name(sel)`, `validate_bet(...)`, `confirm_bet(...)` — would also fix #15 and the missing "canceled" messages in one place.

## Parsers / config loading

17. **Unchecked config loads at startup** (`cycrz.nvgt` ~46-47, 60-65): `parse_jacks_table`, `parse_dice_table`, `parse_combos_table`, `parse_achievements`, `parse_prestige_table`, `parse_quests_table`, `parse_lottery_table`, `parse_tickets_store`. Stores (singles/bundles/prestige) are parsed later in menus, also unchecked. Missing `prestige.store` → `all_standard_prestige_purchased()` returns true and unlocks the Endless menus; missing quests → prestige never pays. Fix: same `length()==0` alert pattern as events/slots/ranks.
18. **`=` in an item line is misread as a menu/category definition** — `single_store.nvgt` ~39, `bundle_store.nvgt` ~48, `prestige_store.nvgt` ~38, `achievements_table.nvgt` ~36 test `line.find("=")` before splitting on `:`. No shipped line trips it; a modder trap. Fix: only when `=` precedes the first `:`.
19. **Fields aren't trimmed; `string_to_int` returns 0 on any non-digit** (`extrafuncts.nvgt` ~120). `min_rank=20 ` → 0 (unlocked at rank 0); `"true "` reads false. Fix: trim each field.
20. **UTF-8 BOM** on a `[settings]` first line makes the whole settings section be ignored. Fix: strip `\xEF\xBB\xBF` from line 1.
21. **Colons in free text shift fields** — combo tier messages use `line.split(":")` (`combos_table.nvgt` ~44) so a colon truncates the message; a colon in an achievement description/hint shifts the reward fields.
22. **Duplicate ids undetected** in every parser; first match wins silently.

## Found in the 7.0 evaluation (2026-10-25)

Not part of the 6.8 audit; found while re-checking it against 7.0 (see [[project_design_review_7_0]] for the design side). Unfixed. Some are player-visible (26, 27, 28, 30). Re-locate by symbol before fixing ([[feedback_verify_code_while_fixing]]).

26. **Confirmed: Scratch all loses leftover tickets.** `lottery_scratch_all` (`lottery_table.nvgt`) splits the batch with `floor(count * weight / totalWeight)` per prize. Leftover tickets are spent but never paid or counted as wins or losses, and one or two tickets usually win nothing. The menu offers Scratch all even with 1 ticket.
27. **Confirmed: reroll charges before checking for a replacement.** `reroll_quest` (`quests_table.nvgt`) takes the cost before checking whether any candidate exists, so with none you pay and nothing changes. Its candidate list also skips `assign_quests`' filters, so a reroll can offer an already-completed tier or a second quest on a stat that's already active.
28. **FIXED (7.1), dev-tested** — two parts. (1) Both Control L handlers (`clicker_game_input` in `game.nvgt`, `minigame_input` in `extrafuncts.nvgt`) call `readdata()` only if `file_exists(currentSaveSlot)`; otherwise they reload config only and say "This game has not been saved yet, so only the configuration files were reloaded." Guard is in the handlers, not `readdata()`, because startup calls `readdata()` before any slot is chosen to set defaults like `xprequired`. (2) Dev-chosen follow-up: `newgamemenu` (`menu.nvgt`) now calls `writedata()` right after `resetgame()` on both paths (overwrite and empty slot), so the fresh game is saved once at start — the overwrite prompt's "erase all progress" is now true immediately, and Control L no longer brings back the erased old run. Not an autosave: later progress still needs Control S / quit-with-save / prestige. Side effect: a new game on an empty slot shows "Highest rank: 1" in the load menu even if quit unsaved. Changelog 7.1 entry 2; readme Save slots + both Control L lines updated. Original: **Confirmed: Control L on a never-saved slot partly wipes the game.** `readdata` loads an empty file, clears baking slots, achievements and the endless counts, and resets `cookieXP` to the current rank's threshold. Money and cookies are kept.
29. **Confirmed: Control L doesn't reload everything.** `reload_config` never re-parses `highlow.table`, `roulette.table` or `tickets.store` (and only resets combo tiers, not the combo settings). Overlaps #14.
30. **NOT A BUG (verified 2026-10-25 in engine source)** — legacy `KeyRepeating` clears the pressed flag, and the Shift `key_repeating` reads run before the plain `key_pressed` reads on both screens, so the announcement never fired ([[project_nvgt_key_pressed_oneshot]]). A defensive `!shift_is_down()` guard was added to the M and C announcements in `clicker_game_input` and `minigame_input` anyway (no behavior change, removes the call-order dependence; no changelog). Original: **Likely: Shift+M and Shift+C fire twice.** In `clicker_game_input` (`game.nvgt`), Shift+M mutes the buffer via `key_repeating(KEY_M)` and the plain `key_pressed(KEY_M)` also announces money; Shift+C copies the buffer item and also announces cookies. Depends on whether `key_repeating` and `key_pressed` both see the same press ([[project_nvgt_key_pressed_oneshot]]); untested.
31. **FIXED (7.1), dev-tested** — thinning modulo and milestone matching compare rank as a double, the eight ticket-shop `int(rank) <` checks use `rank <`, and the prestige history rank (`rankReached`, `prestige_run.rank_reached`, `show_prestige_summary`) is a double read with `read_double` (old int saves convert on read). No `int(rank)` left in code. Original: **Likely: rank logic breaks past rank about 2.1 billion.** `int(rank) % int(rankstep)` (`game.nvgt` rank-up, `check_rank` in `ranks_table.nvgt`) overflows, so announcements stop; milestone matching by `int(rank)` and `int rankReached` in `resetgame` overflow the same way. Same family as #9 and #10.
32. **FIXED (7.1), dev-tested** — `clicker_game_input` F and J handlers rewritten: "Each automated/manual slot produces X … With N slots, you produce Y … in total."; per-slot and total use the bake loops' own formulas (J now divides by `manualSlots` with even splitting, like F); both multiply by `1 + prestige_cookie_multiplier/100`; slot counts via `format_number`; J excludes combo multipliers (they only last during a combo). Changelog 7.1 entry 1; both todo lines moved to finished. Original: **Confirmed, player-facing (found 2026-10-25 from a forum question): F and J production readouts are misleading.** In `clicker_game_input` (`game.nvgt`): (a) both open with "You produce X" where X is the per-slot amount (F) or the raw `manulcookie` (J), so it sounds like total output; (b) they're inconsistent with even splitting on — F speaks `autocookie / slotCount` per slot, J still speaks the full `manulcookie` (the real per-slot share would be `manulcookie / manualSlots`); (c) neither applies `prestige_cookie_multiplier`, which the real bake loops do, so both under-report once that prestige upgrade is bought. Suggested wording: "Each automated slot produces X… With N automated slots, you produce Y… in total." Both have `****Unfinished.` lines in `cycrz/docks/todo_list.txt` (wording + prestige bonus). Not fixed; dev asked for todo entries only.

## Duplication hotspots (bug magnets, not bugs)

- **FIXED (7.1)** — `check_rank()` is now the only rank-up code; `clickergame()` calls it. Original: Rank-up block written twice: `game.nvgt` ~249-288 and `ranks_table.nvgt` ~143+. **7.0 re-check: the copies have diverged** — `game.nvgt` shows a milestone reward in a dialog when baking mode is off, while `check_rank` always speaks it.
