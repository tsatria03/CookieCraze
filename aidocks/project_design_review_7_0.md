# Design review of 7.0 (2026-10-25) — potential improvements

Found during a full-game evaluation (memories + core loop read by hand, plus agents checking balance/config, a rough Python economy sim, and the docs). Saved by the dev as **potential improvements**, not committed work — nothing here is planned or started. Before building any item, write a plan per [[feedback_plan_features_in_memory]] and get a go-ahead ([[feedback_confirm_before_implementing]]). Mark entries **DONE (version)** as they ship. Config numbers are as of 7.0; re-check before acting.

1. **The economy runs away almost at once.** An auto cookie costs 10 cents and earns 50 cents a second. Every item's price grows by only 1.01 per purchase, and percent boosts (yeast_boost, golden_touch…) compound faster than their cost. In the sim, rank 90, where every feature is unlocked, arrived within about 5 minutes. Real play is slower because of menus, but the shape is the same. Speed items stop mattering after about 95 cheap buys (950 cap, [[project_cookiespeed_cap_plan]]), so the 30 or so rank-gated speed items are dead content. Ideas floated: cost growth 1.07–1.15, percent items that grow in cost faster than they pay.
2. **Prestige spam is still live.** `prestige.table` min_rank=5 is 64 experience, and points come from your lifetime quest count on every prestige ([[project_prestige_points_cumulative]]). With 30 lifetime quests, prestige 10 pays 3,000 points, almost the whole 3,395-point standard store. Same as the deferred exploit #7 in [[project_bugs_exploits_balance]].
3. **Endless quests complete instantly after a prestige.** Prestige (`reset_game_state`) resets the dice, higher or lower, roulette and flipper stats, but not blackjack, slots, lottery or combo stats, so `play_blackjack_endless`, `spin_slots_endless`, `scratch_lottery_endless` and `start_combos_endless` start already done. The readme also says prestige keeps minigame stats, which only half matches the code. Same as deferred exploit #8 in [[project_bugs_exploits_balance]]; idea: per-run baseline for endless quests.
4. **Minigames have no economic purpose.** They all lose money (house edges now fair) against an exploding income, and they unlock in a burst, so there's never a "new toy" moment. Ideas: space unlock ranks out, give minigames exclusive rewards.
5. **The settings work as a cheat panel.** A sell price of 100 cents doubles income (default 50), and the Cookie Experience Modifier goes up to 100x. Neither is labelled as a difficulty choice.
6. **Onboarding.** `cycrz/docks/readme.txt` is 1,869 lines. The key list starts at line 507, and about 57% of the file is modder reference. A new blind player has no "first five minutes" section. Related: build/docs #14 in [[project_bugs_build_docs]].
   - **Current sections (mapped 2026-10-25):** welcome intro (1–9), "A note on currency." (11–15), Game features (17–506), Keyboard commands (507–561: In game / In minigames / Buffers / Forms and menus), Configuration files for modders (562–1861, ~70%), Game conclusion (1862–1870). Top-level headings are bare lines with no final period; sub-headings end with a period.
   - **Agreed reorganization (dev said yes 2026-10-25; not done):** 1 welcome intro, 2 new Getting started, 3 Keyboard commands (moved up), 4 Game features, 5 Configuration files for modders, 6 Game conclusion. Move the currency note into the start of the modding section (it already opens with "A note on the word coins in config files", so merge them) or cut the player-facing part to one sentence.
   - **Keys missing from the keyboard section (verified in code):** menus (`deps/custom_menu.nvgt`) — Up/Down arrows, Home/End, first-letter jump, F3 search, Page Up/Page Down menu music volume, Enter to choose, Escape to cancel; dialogs (`deps/dlg.nvgt`) — Enter/Space/A to continue (holding A skips several, A is `key_down`), Escape to close, arrow keys repeat the message, C copies it; button accelerators — every main-screen button has an Alt shortcut from its `&` letter (Alt B bake, Alt S store…), only Alt P on the slot machine is documented now. Note **F3 means two things**: search inside a menu, mute the events buffer on the game screen — say so.
   - Both have `****Unfinished.` lines in `cycrz/docks/todo_list.txt`, alongside the existing getting-started line. Keep every dock line ≤ 1024 chars ([[feedback_dock_line_length_1024]]).
7. **Small config issues:**
   - Gold tickets are gated at rank 15 and diamond at rank 40, but the lottery itself unlocks at rank 30.
   - `achievements.table` defines a lottery category twice ("Cookie lottery" and "Lottery").
   - Combos unlock at rank 90, after automation already dominates.
8. **Store prices don't drop when you lose auto or manual cookies** (forum player request, 2026-10-25). Store price = base × `cost_multiplier`^purchases, using `autocookie_purchases` / `manulcookie_purchases` (`menu.nvgt` "level" lines). Those counters only rise in the store buy paths and reset in `reset_game_state` (prestige/new game); events, flipper, minigame bets, quest rerolls, lottery prizes and rank rewards change only the cookie counts. So a late-run loss leaves the player paying for what they once bought (the player: "You've had millions of these, so now they're prohibitively expensive!"), and free gains never raise the price (why flipping was their way back). Their reading of slots as protecting the count was a misunderstanding — slots multiply output (see code #32 for the F/J readouts).
   - **Proposed approach (discussed with the dev, not decided):** whenever auto or manual cookies decrease, scale the matching purchase count by the share kept: `autocookie_purchases *= newAutocookie / oldAutocookie` (same for manual). Handles any mix of bought and free cookies, can't go below 0, and losing everything returns the base price. Apply at every decrease site (baker events incl. slump/fatigue, flipper, the five minigame bet deductions, quest reroll if `reroll_target` is a cookie type) — ideally via one helper, like `gain_cookiespeed` for speed ([[project_cookiespeed_cap_plan]]).
   - **Watch:** a lost cookie isn't one purchase (items/bundles grant different amounts, percent items); a naive "subtract lost cookies from purchases" lets free cookies push prices below what was ever bought; deliberate losing must never come out ahead. History: an older version priced by current stat and was changed to purchase counts (todo list "Fix shop prices scaling incorrectly based on stat values instead of purchase counts") — check why before reintroducing any stat-based pricing. Has a `****Unfinished.` line in `cycrz/docks/todo_list.txt`.
