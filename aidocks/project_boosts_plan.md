# Boosts (agreed, not built)

Todo item: "Add a temporary boosts shop where you spend cookies or coins on timed power-ups…". Discussed 2026-10-27.

## References surveyed

- **CookieCraze shops:** cookie store `shopmenu()` (menu.nvgt) = buy upgrades / buy tickets (rank 30) / sell / back → "buy boosts" goes after "buy tickets". Tickets are the closest model (inventory `owned`, saved per id, priced `base*mult^owned`, used later from the lottery). **No timed effects exist anywhere** — boosts need a countdown, save of time left, and an expiry announcement. Production hooks in game.nvgt: manual bake (× prestige bonus, × combo), auto bake (× prestige bonus), XP lines, sell price (menu.nvgt ~596), clicktime/speed; F and J readouts repeat the bonus math.
- **Crafting Kingdom** (`user/CraftingKingdom-Windows-main`, third-party, reference only): ~20 boosts (produce % faster, flat production, sale prices %, things % cheaper, Bag of Gold = money per second), all 15 min; instant activation (no inventory); limited by boost slots (start 1, quests unlock up to 4, extra slots for gems); same boost can stack across slots; no extend; End boost; "One of your boosts has run out."; slot list reads "Boost slot 1. <name>" + "XX minutes and YY seconds until boost runs out."
- **Baking slots manager** (menu.nvgt `manage_baking_slots` → Auto slots / Manual slots): Auto slots = "Add a slot" (buy 1…10000, growing price) + "Automate a slot" (list "Slot N (unautomated)" → per-slot menu "Automate this slot for $X" / preview / back; "Automate ALL slots for $X").

## Dev's design so far (2026-10-27)

- **Buy boosts in the cookie store** ("buy boosts"); bought boosts go into an inventory (like tickets).
- **Boost slot manager, modelled on Auto slots:** "Add a slot" (buy boost slots at a growing price) and "Activate a slot" (lists slots; activate one at a time, or activate all). A slot holds one running boost; slots are permanent and reusable.
- **Location (dev, 2026-10-27): a new main-screen button "Boost slot manager", right after "Baking slots manager"** (not inside the baking slots manager — that name reads as slots that bake; boosts aren't baking). Its menu mirrors Auto slots: Add a slot / Activate a slot / Back. **Label "Boost slot ma&nager" — Alt+N (dev)**, pairing with Baking slots &manager (Alt+M); avoid Alt+L (Control L reloads). **Unlock rank — revised (dev, 2026-10-27): 100**, planning for double or nothing too. Full 7.3 ladder: blackjack 10, cookie flipper 20, lottery 30, dice 40, double or nothing 50, higher or lower 60, roulette 70, slot machine 80, baking slots manager 90, boost slot manager 100, combos 110, prestige 120. (Earlier: 90, with combos 100 and prestige 110 — superseded.) **Order (dev): double or nothing is built first in 7.3, then boosts**; otherwise rank 90 would be left empty. Touches: prestige.table `min_rank` 100→120, combos.table `enabled=true:90`→110, ranks.table lines (incl. a new boost unlock line), readme mentions of the old ranks; the 7.2 changelog's "rank 100" stays (7.2 ships first); flag re-locks for saves between old and new ranks. **The cookie store's "buy boosts" unlocks with the boost slot manager (now rank 100)** — always listed in the store, but below that rank it says it's locked, exactly like buy tickets does below rank 30 (menu.nvgt `shopmenu`, "This shop is locked. Please reach rank 30…").
- **Activate a slot flow (dev's idea, 2026-10-27, mirrors Automate a slot):** list of EMPTY slots only ("Slot 1 (empty)") + "Activate ALL slots" + Back → pick a slot → list of boosts you own ("Cookie frenzy, 3 owned. …description") → pick a boost → small menu "Activate this boost for $X" / Back → pay, boost starts, owned count −1 ("Slot 1 is now running Cookie frenzy for 10 minutes."). Errors like automation: no empty slots, no boosts owned (point to the cookie store), can't afford.
- **No free slots** (dev): every boost slot is bought — not even a free first slot. (Matches baking slots: a new game starts with 0 auto and 0 manual slots — cycrz.nvgt reset — first auto/manual slot costs $0.30 each, from main.table.)
- **Activation costs money too (dev, 2026-10-27), like automating an auto slot:** each activation's price grows. main.table [slots] (numbers only — [[feedback_settings_vs_tables]]) gains boost slot base cost + multiplier and boost activation base cost + multiplier, mirroring auto_slot_* and automation_*.
- **Ending is free but confirmed (dev):** **main menu = Add a slot / Activate a slot / End a slot / Back.** "End ALL slots" is NOT on the main menu (dev, 2026-10-27): like Automate ALL, it sits inside the End a slot list after the last running slot (shown only when 2+ are running, as Automate ALL needs 2+), then Back. Same for "Activate ALL slots" after the last empty slot. Each end asks Yes/No. Proposed: an ended boost is discarded (not returned to inventory), which is why it asks.
- Not using Crafting Kingdom's gem/ad pricing or offline replay. **Boosts pause while the game is closed (dev, 2026-10-27, "for right now")** — each running boost saves its time left and resumes on load. Real time IS possible: legacy NVGT `TIME_STAMP` (misc_functions.cpp:80/351) returns Unix seconds; save it, subtract time away on load, clamp negative to 0. Revisit if offline progress is ever added ([[project_feature_ideas]] wish list) — without it, real-time boosts would burn while producing nothing (CK simulates production during its ≤24h catch-up).
